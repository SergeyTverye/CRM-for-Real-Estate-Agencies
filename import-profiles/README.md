# Профили импорта Excel (ТЗ 38)

Профиль описывает одну логическую секцию исходного листа: текстовый **marker** раздела,
набор **ожидаемых заголовков** (сигнатура), сопоставление колонок с полями целевой модели,
поля, **исключённые политикой** минимизации ПДн, и поля с неоднозначным смыслом (**unresolved**),
которые не получают придуманного значения без подтверждения.

- Файл профиля: `<profile_code>.json`, поле `version` — версия mapping; при изменении mapping
  создаётся новый файл/версия, старые задания импорта сохраняют `mapping_version`.
- Детектор секций использует marker + заголовки, а не номера строк: перемещение блока на листе не ломает импорт.
- Если marker найден, но обязательные заголовки не совпали, секция получает статус `unrecognized`
  и не импортируется автоматически.
- Поля `Паспорт`, `Выдан`, `Регистрация` и части даты рождения исключаются **до** формирования
  результатов проверки: они не попадают в БД, `import_row_results`, preview, логи и отчёты.

Синтетический образец файла для проверки: `npm run import:sample` → `data/import-samples/sample-workbook.xlsx`.

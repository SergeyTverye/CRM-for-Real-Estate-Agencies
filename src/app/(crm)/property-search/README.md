# UX поиска объектов

Пикеры клиента и потребности работают по названию и поддерживают клавиатуру. Потребность выбирается через `/api/v1/property-search/pick-needs`; переданный `needId` возвращает также фильтры для предзаполнения. Область видимости потребностей и видимость имени клиента проверяются независимо. Подписи операций и типов берутся из бизнес-справочников.

Районы берутся из `domain/geography`: 10 районов Новосибирска и каталог Москвы. Смена города сбрасывает выбранные районы. Неизвестный город допускает поиск по всему городу.

Все диалоги действий реализованы через общий Modal: закладка, комментарий кандидата, уточнение со сроком, подтверждение переноса, предложение, КП, проверка сотрудника, удаление сохранённого поиска. Для предложения/КП внешнего объявления диалог сначала требует подтверждение переноса.

`GET /api/v1/ai/limits` сохраняет прежний контракт и дополнен `remaining.monthlyBudgetRub` (строка). Read-only query находится в `modules/property-search/queries/ai-limit-queries.ts`, расчёт использует существующие ledger/settings. Предварительное отображение не заменяет серверное резервирование бюджета.

Синхронный API не предоставляет прогресс отдельных источников. UI показывает разбор, ожидание поиска/анализа и завершение без вымышленных процентов. Панель источников содержит статус, число, причину, время завершения запуска и длительность источника при наличии. Сравнение хранит 2–4 выбранных объявления между вкладками до нового поиска.

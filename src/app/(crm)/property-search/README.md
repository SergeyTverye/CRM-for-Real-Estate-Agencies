# UX поиска объектов v3.1

Экран переведён на `/runs` → `/progress` + `/results`. SSR получает только метаданные запуска через application `accessibleRun`; строки читаются постранично. Не добавляйте обратно загрузку всей выдачи через legacy `getSearchRun`.

`catalog-filters.tsx` строит дополнительные признаки по `/filter-catalog`, поддерживает пороги/диапазоны, применимость к назначениям и свежесть. Основное ядро, профили, выбор потребности и подтверждённый AI diff находятся в `search-workspace.tsx`. Ручные изменения формы не запускают платных запросов. Платный AI в проверках этого изменения отключён.

`search-results-v31.tsx`: прогресс источников и остановка, устойчивые серверные страницы с revision и возвратом на первую при 409, все девять сортировок и направления, независимые единицы цены, счётчики вкладок, отдельная неизвестная дата, выделение страницы/всей выборки, пакетные операции по 100 элементов с частичными ошибками, именованные подборки, XLSX/CSV и колонки. Предпочтения колонок сохраняются в localStorage; бизнес-данные туда не записываются. Выделение всей выборки ограничено серверным пределом экспорта 10000 строк и явно читает страницы, обычный просмотр этого не делает.

`SearchFallback` реализует ссылку → при необходимости ручной ввод и официальный файл → dry-run → явный commit → переход к отдельной добавленной выборке. UUID вводить не требуется. Дубли подключены штатным `ListingDuplicateGroups`, проверка площадки — `StartBrowserSession`; после возвращения к поиску опрос получает принятые результаты. AI — готовые `QueryRefinement` и `ListingAnalysisPanel`; никакого фонового вызова модели.

Маркировка: `DEMO` при fixture ENV; открытый сохранённый запуск — `REPLAY · сохранённые данные от …`. Начало нового задания защищено синхронным lock и idempotencyKey; сетевой повтор того же запроса сохраняет ключ. Получение queued-ответа не объявляется завершением поиска.

## Границы текущего серверного DTO

Постраничный `/results` не возвращает `propertyId`, полное членство в именованных подборках и факт предложения для каждой строки. UI поддерживает необязательный `row.propertyId`, показывает подтверждённые факты успешных текущих действий и доступных закладок/кандидатов потребности. Для полного восстановления всех этих меток после нового входа серверу нужно добавить scoped metadata к **текущей странице** (`propertyId`, bookmark, collection memberships, proposed). Загружать ради значков всю legacy-выдачу нельзя. Схему/миграции и чужую серверную зону этот агент не менял.

Production CAPTCHA continuation и платный LIVE AI проверяются соответствующими потоками; подключённые кнопки не означают подтверждение доступности реальных площадок.

## Предыдущая реализация v2.4.1 (история)

Пикеры клиента и потребности работают по названию и поддерживают клавиатуру. Потребность выбирается через `/api/v1/property-search/pick-needs`; переданный `needId` возвращает также фильтры для предзаполнения. Область видимости потребностей и видимость имени клиента проверяются независимо. Подписи операций и типов берутся из бизнес-справочников.

Районы берутся из `domain/geography`: 10 районов Новосибирска и каталог Москвы. Смена города сбрасывает выбранные районы. Неизвестный город допускает поиск по всему городу.

Все диалоги действий реализованы через общий Modal: закладка, комментарий кандидата, уточнение со сроком, подтверждение переноса, предложение, КП, проверка сотрудника, удаление сохранённого поиска. Для предложения/КП внешнего объявления диалог сначала требует подтверждение переноса.

`GET /api/v1/ai/limits` сохраняет прежний контракт и дополнен `remaining.monthlyBudgetRub` (строка). Read-only query находится в `modules/property-search/queries/ai-limit-queries.ts`, расчёт использует существующие ledger/settings. Предварительное отображение не заменяет серверное резервирование бюджета.

Синхронный API не предоставляет прогресс отдельных источников. UI показывает разбор, ожидание поиска/анализа и завершение без вымышленных процентов. Панель источников содержит статус, число, причину, время завершения запуска и длительность источника при наличии. Сравнение хранит 2–4 выбранных объявления между вкладками до нового поиска.

# Обычная браузерная навигация Циана и Яндекса (v3.2.3)

Решение от 09.11.2026 по явному запросу заказчика: для этих двух площадок worker
может использовать `page.goto`, JavaScript страницы и существующие vendor-парсеры
вместо выполнения HTTP через `safeRequest` с последующим `route.fulfill`.
Проверка не распознаётся и не заполняется программно: ожидается выдача до 12 секунд
в рамках общего deadline, затем оставшаяся проверка означает `needs_user_action`.

Яндекс работает headless по умолчанию. Циан использует обычное видимое окно, только
при наличии дисплея; по умолчанию включён на desktop. Headless Docker не запускает
автоматическую проверку Циана и возвращает понятное состояние для существующего HITL.
У каждого источника собственный переключатель в `/settings/sources`; nullable поля
`ai_settings.cian_auto_browser/yandex_auto_browser` сохраняют автоматический выбор
по режиму до явного изменения. Миграции PG/SQLite добавляют только nullable поля.

Chromium persistent profile на площадку хранится в приватном локальном каталоге
`SCRAPER_BROWSER_PROFILE_PATH` (по умолчанию `data/browser-profiles`), вне Git.
Cookies переживают закрытие задания и перезапуск worker; пагинация/детали одного
задания используют одну страницу/context. Chromium сам блокирует параллельное
открытие одного профиля. Между навигациями выдерживается минимум 1,5 секунды,
настроенные пределы страниц/карточек и deadline сохраняются.

Сетевая граница: только HTTPS, фиксированные домены площадок/ресурсов/Servicepipe,
без credentials/нестандартных портов. CDP Fetch проверяет каждый redirect hop и
каждый запрос на принадлежность allowlist и публичный DNS, затем продолжает
нативную сетевую операцию Chromium. Загрузки/попапы/permissions/service workers/
WebSocket ограничены. Stealth, подмена fingerprint/automation flags, proxy и
решение CAPTCHA не используются. В отличие от `safeRequest`, IP здесь не закреплён
для соединения Node.js: TLS/DNS выполняет Chromium. Доверенными остаются только
фиксированные домены, системный DNS и стандартные ограничения локальной сети Chromium.

Обычный HITL сохраняет прежний изолированный профиль/транспорт и RBAC; отсутствие
автоматического результата не выдаётся за пустую рыночную выборку. Профиль native
worker и HITL-профиль различны: перенос cookies между ними не добавляется.
Доступность площадки меняется со временем и подтверждается отдельным LIVE-отчётом,
а логика статусов — REPLAY/fake browser тестами на PG и SQLite.

# Демонстрация на защите

Предусловия: отдельная локальная crm_demo, миграции и обычный seed, подготовленные владельцем среды; затем `npm run db:seed:demo`. Состав и идемпотентность — [demo-data.md](demo-data.md). Пароли берутся из локальной конфигурации и в материалы не включаются. SHA/адрес стенда/дата: **заполняет координатор**.

Для записанных поисков приложение запускают с demo ENV из [контракта поиска](../integrations/property-search-application.md). Плашка записанных ответов обязательна. Fake AI не делает платных вызовов. Для большинства фикстур выбрать Москву; город по умолчанию остаётся Новосибирск.

1. Войти как realtor1. На «Сегодня» показать просрочки и очередь перспективных обращений без актуальной задачи.
2. Зарегистрировать перспективное обращение без объекта. Проверить отказ без следующей задачи, затем назначить срок и исполнителя. Открыть историю клиента/потребности.
3. Из потребности открыть поиск. Ввести запрос, разобрать ИИ в demo-режиме, проверить и изменить фильтры. Показать ручной ввод без ИИ.
4. Запустить записанный success: И/ИЛИ, цена с единицей, этаж, собственник и цитаты. Неизвестные признаки остаются в «Требуют проверки».
5. Запустить partial: HTTP 429 одного источника, успешная выдача сохраняется. Затем failure с разрешённым web-резервом: sourceMethod=web_search, needs_review, однократность. Empty не вызывает автоматический резерв.
6. Поставить закладку и добавить кандидата в подборку. Общий каталог ещё не пополнился. Сохранить поиск, показать ручной повтор.
7. Зафиксировать проверку сотрудника и явно перенести в CRM. Повторить перенос: второй Property не появляется. Отдельно предложить клиенту и показать Match.
8. Открыть объект: обложка, миниатюры, увеличение, документы. Фото синтетические. Пять фото, два документа и частичный сбой проверять по MEDIA.
9. Создать КП из нескольких объектов, поменять порядок/исключить позицию, открыть DOCX и печатный HTML. Новая редакция остаётся draft со снимками исходного КП. «Отправлено» — отдельное действие.
10. Назначить показ; открыть календарь и «Сегодня». Проверить отсутствие дублирующей служебной Task. Чужая личная встреча отображается как «Занято».
11. Показать счётчик уведомлений, чтение и «Напомнить позже» без изменения срока задачи. Рестарт без дублей подтверждает [протокол](../operations/docker-v241-verification.md).
12. В сделке показать участников, несколько комиссий, чек-лист с файлом. При закрытии выбрать постсделочные задачи, исполнителей и сроки.
13. Под realtor2 проверить чужую карточку и файл прямым запросом по SEC. Под manager показать KPI/drill-down и настройки/журнал ИИ.
14. Завершить фактическими тестами, ограничениями площадок и экономикой. Назвать неизмеренные NFR-14, нагрузку и время операций.

E2E и подлинные DEMO/LIVE снимки этапа 2 зафиксированы: [приёмка](../acceptance/stage2-live-ai-ux.md), [реестр](screenshots.md). Это инструкция, не протокол успешного прохождения. Результаты: [test-protocol.md](test-protocol.md) и [VKR](../acceptance/v241/VKR.md).

# Живые испытания Yandex AI и поиска — 05.11.2026

Режим: **LIVE**. Демо-клиенты CRM синтетические; объявления получаются с действующих площадок. Фикстуры выключены. Исполнитель запускает `scripts/vkr/live-ai.ts` на `crm_demo`, `http://localhost:3310`, от realtor1. У руководителя временно устанавливается месячный бюджет 250 ₽; ENV-потолок 1000 ₽ не повышается. Исходные настройки сохраняются локально вне Git и восстанавливаются через manager API в `finally`. Секреты и сессии не включаются в доказательства.

## Тариф, источник и границы учёта

Проверено веб-поиском и открытием [официального прайса Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing) 05.11.2026: синхронная Alice AI LLM Flash — 0,1 ₽/1000 входных токенов и 0,2 ₽/1000 выходных; кешированные и инструментальные токены — 0,025 ₽/1000; web_search — 915 ₽/1000 вызовов (0,915 ₽/вызов). Цены с НДС. CRM использует консервативный расчёт всех входных токенов по полной цене: 100 ₽/млн input, 200 ₽/млн output, 0,915 ₽/web-call. Льготы кеширования не предполагаются.

Тариф обновляется отдельной версией через `PUT /api/v1/settings/ai`, не прямой SQL-записью. Тарифная история сохраняется после восстановления пользовательских настроек. Доступа к биллингу Yandex Cloud нет: вычисленная по usage стоимость CRM не выдаётся за подтверждённое списание Cloud.

Пределы: не более 10 подборов, 5 вызовов Yandex Web Search и 25 прочих AI-вызовов. Повтор платной ошибки допустим только после исправления причины. Бюджетные гонки и исчерпание проверяются исключительно offline/fake.

## Подготовка и выявленные ошибки

- `ТЗ.txt` отсутствует; актуальные нормативные документы — `ТЗ_CRM_итоговое_v2.4.1_проверено.md` и `tz.md`.
- До первого платного вызова устранён унаследованный нестандартный `NODE_ENV` у dev-процесса; сервер запускается с `development`. Для HMR используется localhost.
- Изменения других агентов временно нарушали сборку `/settings/ai` и `/today`. Эти файлы не исправлялись данным исполнителем; неудачные открытия UI не считаются вызовами Yandex.
- У скрапера выявлен отдельный тайм-аут на каждую площадку после ожидания очереди. Исправлено: единый дедлайн задания, запрет запуска следующей площадки после его истечения, ограниченный cleanup; application оставляет 2 секунды на возврат частичного результата. Offline-регрессия подтверждает сохранение первого результата и восстановление следующего задания.

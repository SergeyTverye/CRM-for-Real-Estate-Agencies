Режим: **LIVE**. Демо-клиенты CRM синтетические; объявления получаются с действующих площадок. Фикстуры выключены. Исполнитель запускает `scripts/vkr/live-ai.ts` на `crm_demo`, `http://localhost:3310`, от realtor1. У руководителя временно устанавливается месячный бюджет 250 ₽; ENV-потолок 1000 ₽ не повышается. ## Тариф, источник и границы учёта

Проверено веб-поиском и открытием [официального прайса Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing) 05.11.2026: синхронная Alice AI LLM Flash — 0,1 ₽/1000 входных токенов и 0,2 ₽/1000 выходных; кешированные и инструментальные токены — 0,025 ₽/1000; web_search — 915 ₽/1000 вызовов (0,915 ₽/вызов). Цены с НДС. CRM использует консервативный расчёт всех входных токенов по полной цене: 100 ₽/млн input, 200 ₽/млн output, 0,915 ₽/web-call. Льготы кеширования не предполагаются.

Тариф обновляется отдельной версией через `PUT /api/v1/settings/ai`, не прямой SQL-записью. Тарифная история сохраняется после восстановления пользовательских настроек. Доступа к биллингу Yandex Cloud нет: вычисленная по usage стоимость CRM не выдаётся за подтверждённое списание Cloud.

Пределы: не более 10 подборов, 5 вызовов Yandex Web Search и 25 прочих AI-вызовов. Повтор платной ошибки допустим только после исправления причины. Бюджетные гонки и исчерпание проверяются исключительно offline/fake.

### Исправления и границы проверки

- Инструкция веб-поиска требует прямые карточки с ID, запрещает каталоги, подборки и конструирование URL; при отсутствии карточек требует `candidates=[]`. Детерминированная проверка поддерживает Циан, Авито, Домклик, Яндекс Недвижимость, Мир Квартир, OnRealt, Юлу. Неподдерживаемый домен/шаблон, небезопасный URL и каталог отклоняются с кодом причины; агрегат причин сохраняется в статусе web-источника.
- `YANDEX_WEB_SEARCH_ALLOWED_DOMAINS` поддерживает до **пяти** доменов в одном запросе (существующее ограничение конфигурации). В этих двух вызовах: `cian.ru,mirkvartir.ru,onrealt.ru,realty.yandex.ru,domclick.ru`. Валидатор знает все семь площадок; произвольные неизвестные домены запрещены даже при пустом ENV-списке. Исходные `sources` подбора сохранены в evidence.
- Добавлена серверная проверка доступности максимум пяти страниц: SSRF/DNS pinning, 4 с, максимум 2 МБ, без переходов по redirect, без retry и выполнения HTML. Блокировка, CAPTCHA, иной HTTP или недоступность оставляют `needs_review`. Успешный HTML также не подтверждает цену, актуальность и собственника. Реальных карточек во втором заходе не было, поэтому этот этап подтверждён **unit-тестами**, а не живым чтением карточки.
- Диагностика Циана: обычный HTTP вернул **200, 2280 байт**, строку CAPTCHA, без `OfferCard` и `legacy-commercial-serp-frontend`; штатный парсер дал `PARSE_FAILED`. Это страница ограничения доступа, а не доказанный дефект селекторов. Проверен браузерный режим через настройку руководителя, `SCRAPER_BROWSER_ENABLED=true`, `SCRAPER_BROWSER_EXECUTABLE_PATH=D:/chrome-win64/chrome.exe`; CAPTCHA не решалась, обход не применялся. Циан остался **blocked/0**.
- В промежуточном адаптере для запуска и снимка 32 CAPTCHA нормализовалась в 403. Поэтому `ACCESS_BLOCKED HTTP 403` на нём — классификация адаптера, **не доказательство исходного HTTP-статуса браузерной страницы**. Финальный код распознаёт CAPTCHA на границе парсера как `ACCESS_BLOCKED; CIAN_ACCESS_CHALLENGE (CAPTCHA/антибот)` без выдуманного HTTP-кода. Эта корректировка подтверждена отдельной unit-регрессией на HTTP 200; дополнительного живого подбора сверх лимита не было.
- В начале выявлены ограничения конфигурации (минимальный `SCRAPER_JOB_TIMEOUT_MS=1000`, до пяти web-доменов). Ошибки до dispatch не потребляли платные вызовы. Временная ошибка dev-manifest прервала получение настроек при cleanup; после перезапуска исходные настройки восстановлены через API. Локальные снимки настроек сохранены только в игнорируемом `data/`.

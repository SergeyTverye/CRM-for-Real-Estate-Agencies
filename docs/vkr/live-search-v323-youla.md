# Юла — жилая недвижимость и качество выдачи v3.2.3

Проверка: 2026-11-08/09, Новосибирск. Публичные страницы и API самой Юлы,
обычный HTTP, без обхода защит. Лимит исчерпан: 30 попыток всего, включая
отклонённую sandbox-попытку и одно открытие web-инструментом. Между запросами
скриптов — не менее 1100 мс. Секреты CRM и данные Excel не использовались.
Машиночитаемые результаты: `live-search-v323-youla.json`.

## LIVE: маршруты и данные

Префикс: `https://youla.ru/novosibirsk/nedvijimost/`.

| Сценарий | Категория | Код | Продуктов / в городе | Следующая страница |
| --- | --- | --- | --- | --- |
| Продажа квартиры | prodaja-kvartiri | 2001 | 30 / 26 | да |
| Аренда квартиры | arenda-kvartiri | 2005 | 30 / 25 | да |
| Продажа комнаты | prodaja-komnati | 2002 | 30 / 30 | да |
| Аренда комнаты | arenda-komnati | 2006 | 30 / 29 | да |

Повторный LIVE-прогон реализованного парсера со штатными web-заголовками:
квартиры в аренду — 24 после проверки города; офисы — 4; склады в аренду — 0,
в продажу — 0. У обоих складских ответов `hasNextPage=false`: это подтверждённый
ноль в момент проверки, а не доказательство отсутствия предложения навсегда.
`165974` подтверждён как «Склад» в SSR-справочнике площадки, исправлять его не нужно.

Обнаруженная особенность: без `uid`/`x-uid` API отвечает HTTP 200, но игнорирует
выбранные native-фильтры. Десять диагностических запросов без этих заголовков
признаны INVALID_SAMPLE и исключены из приёмочных чисел. Парсер использует
случайный публичный идентификатор web-клиента по штатному контракту пакета.
Это не аутентификационный токен и не механизм обхода защиты.

SSR `window.__YOULA_STATE__` даёт города, дерево категорий и определения фильтров.
Выдача: POST `https://api-gw.youla.ru/graphql`, операция `catalogProductsBoard`,
persistedQuery hash из штатного контракта пакета, проверенный LIVE. В variables:
attributes/categories, location.city, search и непрозрачный cursor. Ответ содержит
`data.feed.items[].product` и `pageInfo.cursor/hasNextPage`. Элементы рекламы
без product пропускаются. Иногородние promoted-карточки исключаются по city ID;
отсутствующий city ID также не считается подтверждением города.

Цена — `price.realPrice.price / 100`, фото — `images[].url`, адрес —
`location.addressText`; площадь в feed берётся из названия. Комнатность:
`komnat_v_kvartire`, 0→10660, 1→10654, 2→10655, 3→10656, 4→10657.
Пять и более не выдаются за точные пять комнат. Общая площадь и цена в native
range-фильтрах имеют масштаб x100. Студия — отдельная ветка квартир с ID 10660.

Две LIVE-карточки (продажа/аренда квартиры) подтвердили details SSR:
`realty_obshaya_ploshad.rawValue / 100`, `realty_etaj`, `komnat_v_kvartire`,
`location.description`, `datePublished.timestamp` и `dateUpdated.timestamp`
(Unix seconds). Их parsing воспроизведён обезличенными фикстурами.
Техническое время загрузки не подменяет дату публикации.

## Реализация и REPLAY

`src/modules/property-search/infrastructure/youla-parser.ts` расширяет parser
в `extendSourceParsers`; vendor и node_modules не изменяются. Жилая защита
снята только для Юлы. Разбор инертного JSON не исполняет код страницы.
Выход формируется по whitelist, без users/owner/телефонов и свободных описаний.
Ссылки проверяются на HTTPS и домен площадки. Детали связываются по ID карточки;
чужая карточка не может снабдить результат датой или площадью.

Между запросами парсера выдерживается не менее 1100 мс; ожидание отменяется
через AbortSignal. Детали ограничены тремя карточками на client/job (настройка maxCards, максимум 10),
общим deadline и AbortSignal. Недоступная detail сохраняет известные факты feed;
CAPTCHA/rate-limit/abort не превращаются в пустой успешный результат. Снятые
с публикации карточки, обнаруженные в details, исключаются.

REPLAY проверяет категории, масштаб чисел, комнатность, пустой feed, сторонние
города/URL, курсор, изменение cursor, сохранение даты, отсутствие периода аренды,
ошибки схемы/доступа, бюджет деталей и общий адаптер поиска. Интеграционный тест
проверяет сохранение снимка, неизвестную единицу аренды и запрет чужого run.

## Границы подтверждения

- Единица аренды остаётся неизвестной: даже «аренда длительно» не подтверждает
  оплату за месяц. Явное `/мес.` распознаётся существующей нормализацией.
- Поля, отсутствующие в feed и не загруженные в пределах бюджета details,
  остаются неизвестными. Район выделяется только из явного адреса/поля.
- Коттеджи/таунхаусы не имеют отдельно проверенного контракта: существующий
  общий поиск сохраняет flat/studio/room/house и сообщает частичное покрытие.
- Коммерческий feed не содержит доказательств подтипа/операции: они появляются
  после details. Запрошенный фильтр не подставляется как факт объявления.
- Корректный переход по cursor проверен REPLAY. LIVE-проба второй страницы
  попала в INVALID_SAMPLE без uid; подтверждён только формат курсора initial feeds.
- UI/browser e2e и DEMO в этой задаче не запускались. LIVE не заявляется
  end-to-end проверкой CRM; данные проверены на уровне публичного источника/парсера.

schema от генерации не включены. Замечание pg о параллельном client.query
из существующего тестового окружения не повлияло на результат.

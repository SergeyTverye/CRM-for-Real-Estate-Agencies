# Демонстрационные данные ВКР

Набор предназначен для локальной БД **crm_demo** и целиком синтетический. ФИО вымышлены, телефоны имеют вид `+7 900 000-xx-xx`, email — `@example.ru`. Адреса коммерческих объектов условные. Клиенты распределены между `realtor1` и `realtor2` (13/12). Маркер данных — `[DEMO-V241]`.

## Подготовка и запуск

Требуются уже применённые миграции, обычный Prisma seed (пользователи manager/realtor1/realtor2, справочники, юридические лица, AiSetting и тарифы) и установленный набор зависимостей. Демо-скрипт не запускает миграции, generate или установку пакетов. Пароли учётных записей задаются обычным seed через `SEED_*`; скрипт их не меняет и не печатает.

Задайте `DATABASE_URL` для локальной **crm_demo** в окружении процесса или `.env.local`, затем:

```powershell
npm run db:seed:demo
npm run db:seed:demo
$env:TEST_DATABASE_URL = $env:DATABASE_URL
npx vitest run --config scripts/demo/vitest.config.mts --reporter=dot
npx tsc --noEmit
npx eslint --config scripts/demo/eslint.config.mjs scripts/demo --max-warnings=0
```

Программа откажется работать с БД, имя которой отличается от crm_demo. Успешный seed печатает только JSON со счётчиками ключевых таблиц. `.env.local`/`.env` загружаются без вывода значений; переменные процесса имеют приоритет.

Идемпотентность обеспечивают стабильные UUID новых записей, уникальные связи и проверки конкретных бизнес-записей. Клиенты, потребности, объекты, задачи, показы и события предыдущего частичного seed подхватываются по их демонстрационным признакам. Нет общего раннего выхода по наличию первого клиента. Незавершённый набор дополняется, существующие редакции КП сохраняются. Повторный запуск не меняет сроки задач, не сбрасывает прочтение уведомлений и не создаёт новые поисковые прогоны. Даты вычисляются от сохранённой даты первого демо-клиента; существующие сроки не сдвигаются при повторе.

## Поиск и AI: происхождение данных

Seed принудительно включает **только в своём процессе** `SCRAPER_DEMO_FIXTURES=true`, `SCRAPER_ENABLED=true`, `AI_ENABLED=true`, `YANDEX_WEB_SEARCH_ENABLED=true`, `YANDEX_WEB_SEARCH_AUTO_FALLBACK=true`; ключ провайдера не требуется. В AiSetting БД crm_demo включаются скрапер, ИИ, ручной/автоматический веб-резерв и площадки cian/mirkvartir/avito. Платные вызовы не выполняются: application-слой выбирает FixtureScraperAdapter и FakeResponsesProvider, сохраняя обычные проверки разрешений, лимитов и тарифов.

Для интерактивного повторения этих сценариев **процесс приложения** также запускайте с `SCRAPER_DEMO_FIXTURES=true` и соответствующими разрешениями ENV, описанными в `docs/integrations/property-search-application.md`. Изменений `.env` скрипт не делает. Обычный запуск приложения без ИИ сохраняет ручные функции и ранее созданные подборки.

Фикстуры `tests/fixtures/scraper/` содержат записанные синтетические результаты. География большинства — Москва: сохранённые поиски используют её явно, не изменяя общий город по умолчанию Новосибирск. Источники каждого прогона и причины отказов помечены «ДЕМО / записанный ответ». Полный отказ заканчивается общим статусом partial после успешного веб-резерва: отказ скрапера остаётся виден в источниках. Веб-кандидат имеет sourceMethod=web_search и needs_review; он не выдаётся за подтверждённый объект. Фотографии площадок не скачиваются; галерея перенесённого объекта также полностью синтетическая.

Оценка и условный факт в 6 ручных записях AiUsageLog вычислены по токенам и стоимости web_search_call из AiTariff, а не являются счётом внешнего провайдера. `result.demo=true`, `mode=test` и пояснение явно обозначают это. Автоматическая запись FakeResponsesProvider также дополнительно помечена как демонстрационная. Эти данные нельзя использовать как измерение стоимости или доступности живой интеграции.

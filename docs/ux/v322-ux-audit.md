Дата: 08.11.2026. Ветка: `feature/ux-search-v3.2.2-ux`.

## Метод и границы

Выполнены визуальное сравнение пар снимков и фактический прогон Playwright: исходная **6ee543c** на `http://127.0.0.1:3370`, интеграция UX **d881253** на `http://127.0.0.1:3371` (с дополнительными документами договоров). Оба сервера оставлены работающими. Синтетическая база `crm_demo`, роль `realtor1` для первых семи маршрутов, `manager` для отчёта. Замер: 1366×768; визуальное сравнение: 1366×768, 1920×1080 и 390×844. Ввод текста, прокрутка и выбор значений обычных полей не считаются; переходы, раскрытия, выбор результата обращения, отметки объектов и команды сохранения считаются. Числа ниже — выполненные действия, а не оценка по исходному коду.

Повторяемый сценарий: [v322-ux-clicks.mjs](../../scripts/vkr/v322-ux-clicks.mjs). Машиночитаемое свидетельство: [16 успешных прогонов, шаги и HTTP-статусы](v322-click-measurements.json). Каждый сценарий выполнен на обеих версиях; сохранения обращались к настоящему API, без подмены ответов. Скрипт предназначен только для этих демонстрационных серверов: создаёт по одному синтетическому обращению с потребностью/следующим действием, задаче и КП на сервер за прогон. Параметры существующей потребности сохранены без изменения значений; новая синтетическая задача действительно перенесена на час (в этом прогоне — через местную полночь). Данные тестовых созданий не выдаются за исходные скриншоты.

Бизнес-правила, RBAC, серверные API, поиск объектов, договоры и компоненты документов не изменяются. Договоры исследованы только для общего сценария сроков. Передача клиента, разрешение дублей, подтверждения доступности объекта и контроль конкурентных изменений сохраняются.

## Детали проверки интерфейса

- **Иерархия:** обязательный запрос и следующее действие не скрываются. Исторические цены/условия КП продолжают формироваться прежним API. Сворачивание не очищает данные и не меняет payload.
- **Подписи:** «Объявление, по которому обратились», «Объект из каталога», «Карточка объекта», «От имени ИП или ООО» вместо технических/сокращённых пояснений.
- **Пустые состояния:** поиск клиента предлагает проверить контакт/фильтры; пустая подборка указывает два конкретных пути добавления.
- **Ошибки:** скрытый раздел открывается при ошибке соответствующего поля; summary подсказывает, где исправить данные. Нативная ошибка ввода также раскрывает раздел. Общие отказ доступа, конфликт версии и серверная ошибка продолжают проходить через `FormErrorBanner`.
- **Подтверждения:** не добавлены к обратимому раскрытию; существующие подтверждения передачи/архива/доступности не удалены.
- **Сохранение:** `DisclosureSection` использует нативный `details/summary`, не условный рендер содержимого. Введённый текст, состояние выбора и узлы ввода сохраняются. Управление summary доступно клавиатурой. Заполненный вводный текст/заметки КП, комментарий рекламы и способ оплаты потребности изначально раскрываются.
- **Мобильный экран:** новые действия списка переносятся по строкам; сворачиваемые блоки не задают фиксированной ширины. Композиция 390 px проверена по парам снимков: блоки помещаются по ширине, названия переносятся, фиксированная нижняя панель остаётся прежней. Дополнительно выявлена узкая область нажатия на summary — исправление описано ниже.

## Снимки ДО / ПОСЛЕ

Скрипт: `scripts/vkr/v322-ux-screenshots.mjs` (Playwright Chromium, без новых зависимостей).

```powershell
# Учётные данные заранее переданы окружением; значения не печатаются и файлы .env не читаются.
node scripts/vkr/v322-ux-screenshots.mjs http://127.0.0.1:3000 data/ux-before
node scripts/vkr/v322-ux-screenshots.mjs http://127.0.0.1:3000 data/ux-after
```

Требуются `SEED_MANAGER_LOGIN`, `SEED_MANAGER_PASSWORD`, `SEED_REALTOR1_LOGIN`, `SEED_REALTOR1_PASSWORD` и установленный Chromium (`npx playwright install chromium`). При отдельном каталоге браузера задайте `PLAYWRIGHT_BROWSERS_PATH`.

Использовать только синтетическую БД. Скрипт снимает «Сегодня», обращение, списки клиентов/потребностей/подборок/КП/задач, формы, планер, каталог, истекающую рекламу и договоры; руководителю дополнительно — общие задачи и отчёт. Карточки клиента/потребности/подборки/КП/задачи, историю, потребности клиента и изменение потребности находит по доступным ссылкам списка, без прямого чтения БД. Отсутствие подходящей записи отмечает в `manifest.json`; для полного сравнения следует наполнить синтетическую базу заранее.

Для каждой роли размеры: **1366×768, 1920×1080, 390×844**. Снимок фиксирует viewport, без маскировки переполнений через fullPage. Манифест содержит роль, маршрут, размер, время, SHA скрипта и SHA-256 PNG. Версию запущенного сервера передайте через `CRM_SCREENSHOT_REVISION` (например, `6ee543c` для исходной версии); без неё `revision: null`, поскольку локальный HEAD скрипта может отличаться от работающей сборки. Пароли, cookies, тела ответов и HTML не записываются. Запросы браузера вне базового origin и операции записи блокируются; вход/выход выполняются отдельно. Скрипт не сохраняет формы, не запускает поиск или AI. Для сопоставимости до/после должны использоваться одна база, одинаковые данные/часовой пояс и чистые сборки соответствующих коммитов.

**Статус:** координатор предоставил по **138 снимков** до и после. Проверены SHA-256 всех 276 PNG: расхождений нет. Оба манифеста `complete: true`; по два пропуска относятся к карточкам подборки и задачи руководителя, отсутствовавшим в его исходном списке. Подборка и задача риелтора присутствуют. Исходные снимки сохранены, after добавлены в Git. Это снимки интеграции d881253, до двух небольших исправлений, описанных ниже.

### Исправления после просмотра

1. `src/app/(crm)/clients/page.tsx`: запрет переноса основного контакта на desktop (`whitespace-nowrap`). Новая колонка быстрых действий сжимала телефон и разрывала номер на две строки. Существующий мобильный стиль таблицы сохраняет перенос в карточках.
2. `src/ui/disclosure-section.tsx`: мобильный `summary` получает минимальную высоту 44 px и вертикальный отступ. Ранее рамка визуально была достаточно большой, но кликабельный заголовок оставался высотой в строку текста; теперь область нажатия больше. На desktop размеры прежние.

**Нужны пересборка и пересъёмка after координатором.** Текущие ссылки честно показывают d881253 до этих двух правок; их визуальная приёмка на новой сборке ещё не выполнена. TypeScript, ESLint и 13 тестов после правок прошли. Серверы не перезапускались и не пересобирались.

Первоначальный блокер обязательной смены пароля устранён координатором перед текущим прогоном; все 16 маршрутов теперь выполнены. Переменные загружались из `.env` собственной копии через `dotenv` с `quiet: true` по разрешению координатора; значения не выводились.

# Доверенное локальное профилирование XLSX (§12.1, DT-22)

Инструмент работает офлайн на машине координатора. Агент разрабатывал и проверял его **только на синтетике**. Это подготовительный инструмент, а не импортёр: он не выполняет dry-run/commit, не подтверждает mapping и не означает PASS DT-22.

```powershell
node scripts/private-import/profile-workbook.mjs <путь> --out private-data/workbook-profile.json
```

Команда пишет одинаковый JSON в stdout и файл. Запускать только в доверенном локальном терминале, без записи в CI/облачные журналы; не присылать автоматический вывод агентам. Выходной файл должен отсутствовать: инструмент отказывается перезаписывать существующие файлы, включая исходную книгу и ссылки. Для повторного запуска выбрать новое имя. Ошибки дают код 1 и фиксированное сообщение без пути, текста книги или stack trace. Успех — код 0.

`private-data/` уже исключён из Git; профиль не коммитить. Обезличенную выжимку координатор готовит вручную после локальной проверки. Хэши не являются криптографической анонимизацией: короткие имена/заголовки допускают словарный перебор, поэтому даже профиль хранить в закрытом контуре с ACL. На Windows `mode:0600` не заменяет ACL пользователя. Программа не создаёт копий исходной книги или временных файлов.

## Контракт JSON v1

- Книга: число листов, определённых имён, признак внешних Excel-связей; макросы запрещены (наличие vbaProject.bin приводит к отказу). Гиперссылки считаются отдельно и не означают внешнюю Excel-связь.
- Лист: порядковый номер; SHA-256 имени (первые 8 hex) и длина UTF-16; видимость; размеры по ExcelJS rowCount/columnCount (включая оформленные ячейки); объединения, скрытые строки/колонки, автофильтр, split/frozen-панели, диапазоны ширин, счётчики правил условного форматирования, проверок данных, изображений, примечаний и гиперссылок. Координаты проходят строгую проверку A1; тексты, имена, URL, сообщения проверок и содержимое картинок/комментариев не выводятся.
- Блок: эвристический headerRow, dataStartRow, endRow, startCol/endCol. Кандидат — ≥3 текстовых ячеек перед непустой строкой, если предыдущая строка содержит <3 текстовых ячеек либо ≥2 заголовка распознаны словарём. Конец — первая пустая строка или следующий кандидат. Объединённые ячейки считаются только по master. Эвристика не гарантирует распознавание соседних горизонтальных таблиц и необычных шапок; такие случаи координатор проверяет локально. Профиль не является утверждённым mapping.
- Колонка: индекс/буква; локальный семантический класс заголовка, SHA-256 (8 hex), длина; unknown имеет unresolved=true. Заполненность, взаимоисключающие typeCounts/typeRatios, признаки телефона/e-mail/текстовой даты/денежного формата, длины строк, кардинальность, доля дублей. Доли типов считаются от всех строк, сигналы и доля дублей — от заполненных. Формулы не вычисляются, их кеш не профилируется как отдельное значение; дата Excel определяется ExcelJS по формату. RichText и hyperlink — отдельные типы.
- NumberFormats: исходный numFmt ID из OOXML, хэш и фиксированный класс. **Сырые строки форматов намеренно не выдаются**: в литералах формата могут быть ПДн. FormulaShapes: только имена функций из фиксированного allowlist, число неизвестных вызовов и числовые смещения A1-ссылок относительно ячейки. Литералы, листы, внешние/структурированные ссылки и имена пользователя не выдаются. Абсолютные ссылки также представлены смещениями; это структурная сводка, не исполняемая формула.
- Дубли: duplicateRows и duplicateAddressArea — число повторных строк сверх первого экземпляра на листе среди обнаруженных блоков. Совпадения точные, без бизнес-нормализации, без auto-merge; сравнение ведётся по SHA-256 только в памяти. В JSON нет ни ключей сравнения, ни значений. Пустая пара address+area не считается.

Защита ресурсов: ≤64 MiB сжатого файла, ≤256 MiB объявленного распакованного ZIP, ≤2 млн ячеек прямоугольника на лист. DTD/entities и имена листов >31 символа отклоняются (ExcelJS иначе может вывести имя в warning). Неизвестные/повреждённые книги могут отклоняться. Нет выполнения макросов, формул или внешних запросов; нет AI/сетевого клиента. Ограничения не заменяют изоляцию процесса при работе с намеренно враждебным XLSX.

## Воспроизводимая синтетическая проверка

```powershell
node scripts/private-import/make-synthetic-workbook.mjs
npx vitest run --project unit tests/unit/private-import-profiler.test.ts
```

Генератор создаёт `tests/fixtures/synthetic/workbook-like.xlsx`: три листа (visible/hidden/veryHidden), несколько блоков, объединение, скрытые строка/колонка, денежные/датовые форматы, формулы и кеш, телефоны, e-mail, richText, ссылки, комментарий, картинка, validation/conditional formatting и дубли. Тест собирает все исходные строковые значения, формулы, URL, имена листов/диапазонов, заголовки, примечания и форматы и требует их отсутствия в JSON; проверяет также ошибки и сохранность существующего выхода. Реальную книгу тесты не открывают и не ищут.

# Защита конфиденциальных данных

Основание: ТЗ v3.2.1 §11, §12.1, DT-24. Рабочая книга предприятия и её копии/производные — коммерческая тайна. Агенты работают только с синтетикой. Реальную книгу запрещено передавать LLM, AI API, Git, Docker context и CI. Не прикладывать локальные отпечатки к отчётам и артефактам: SHA-256 не защищает низкоэнтропийные значения от перебора.

## Локальная проверка

    node scripts/security/install-hooks.mjs
    npm run security:guard
    npm run security:guard -- --artifacts
    npm run security:guard -- --artifact desktop-artifacts --artifact release

Установщик создаёт исполняемый .git/hooks/pre-commit, запускающий guard из корня репозитория. Повторная установка допустима. Чужой существующий хук или core.hooksPath вызывают отказ без перезаписи. Хук не устанавливается автоматически при npm install. Git --no-verify может обходить локальные хуки, поэтому CI gate обязателен.

Guard проверяет git ls-files -z и git diff --cached --name-only -z: запрещены имя рабочей книги в любом каталоге, Office ~$*, private-data, data/private-imports, crm-secrets, clouds.env, *.crmbackup, *.dump/*.sqlite/*.db (включая SQLite WAL/SHM). Для дампов разрешено только tests/fixtures/synthetic/. Файлы по запрещённым путям не открываются; имена проверяются с NFKC и без учёта регистра.

Контент берётся из индекса Git, а не из рабочей копии: изменение файла после git add не скроет утечку. Удалённые файлы не читаются, запрещённый tracked-путь всё равно блокирует gate до удаления из индекса. Рабочее дерево и вся Git-история автоматически не анализируются. Несвязанные untracked/ignored-файлы не читаются; для артефактов нужен отдельный режим.

Без private-data/fingerprints.json выводится CG_NAMES_ONLY: проверяются только имена/пути, контент не читается. Наличие файла включает сравнение с SHA-256; некорректный файл блокирует gate. Формат — JSON-массив lowercase SHA-256 (64 hex-символа), без значений и дополнительных полей. Пустой массив допустим, контентных проверок тогда нет.

Режим --artifacts рекурсивно проверяет test-results, playwright-report, docs/**, src-tauri, dist, включая ignored-файлы. Отсутствующие стандартные каталоги допустимы. Явно заданный --artifact обязан существовать и находиться внутри репозитория. Симлинки/junctions, недоступные файлы и неподдерживаемые типы файлов блокируются; переход через родительские симлинки запрещён.

ZIP/XLSX распаковываются только в памяти, без создания файлов и выполнения макросов/формул. Проверяются имена участников, UTF-8/UTF-16LE тексты, sharedStrings, inline strings, rich-text и сохранённые числовые значения XML. XML entities декодируются, DTD запрещён. Вложенные ZIP определяются и по сигнатуре, включая переименованные файлы. Ошибки архивов, traversal, превышение лимитов дают отказ. Лимиты: вход 256 MiB, распаковка 128 MiB на архив, участник 32 MiB, 10000 участников, вложенность до 4 уровней.

Вывод guard — только CG_* и JSON-экранированные пути, без исключений библиотек, строк, значений или хэшей. Для архивов выводится лишь внешний путь, без имён участников. Код выхода 0 — проверка пройдена, 1 — отказ. Основные коды: CG_PATH, CG_FINGERPRINT, CG_FINGERPRINTS_INVALID, CG_ARCHIVE_INVALID, CG_XML_INVALID, CG_LIMIT, CG_FILE_TYPE, CG_READ, CG_SCOPE, CG_ERROR, итог CG_PASS/CG_FAIL.

## Отпечатки: только доверенный локальный контур

**Агентам запрещено запускать следующую команду на реальной книге. Это делает координатор локально, без LLM/CI.**

    node scripts/security/make-fingerprints.mjs "/absolute/path/to/workbook.xlsx"

Инструмент читает только явно переданный файл через ExcelJS, не исполняет формулы и внешние ссылки. Включает строки, rich-text, отображаемый текст hyperlinks, кешированные результаты формул и даты. NFKC, lowercase, trim, схлопывание пробелов; строки от 4 символов, числа от 5 цифр. Телефоны дополнительно приводятся к цифрам; российская 8 для 11 цифр нормализуется к 7. Хранятся только уникальные SHA-256 в private-data/fingerprints.json, stdout — только количество. Ошибка даёт код 1 без вывода значений; при CI запуск запрещён. На Windows защищённый каталог должен иметь ACL текущего пользователя; POSIX mode не заменяет ACL.

Синтетическая фикстура: tests/fixtures/synthetic/confidential-like.xlsx, создана ExcelJS без чтения внешних книг. Тесты создают временные Git-репозитории и свой локальный synthetic-only файл отпечатков; реальный private-data не меняют.

## CI перед публикацией

Шаг непосредственно ПЕРЕД actions/upload-artifact, после сборки:

    - name: Confidential artifact gate
      shell: pwsh
      run: ./scripts/security/ci-guard.ps1 --artifact desktop-artifacts

На Linux: sh scripts/security/ci-guard.sh --artifact desktop-artifacts. Обёртки проверяют Git и стандартные каталоги, передают дополнительные аргументы, сохраняют ненулевой exit code. Указывать все фактические пути публикации явно, включая нестандартные каталоги и installer staging. Не использовать continue-on-error или if: always() для публикации после отказа. Fingerprint-файл не коммитить/загружать для CI: CI работает на синтетике, отсутствие файла означает только проверку путей. Контентная проверка реальных производных выполняется доверенным координатором локально перед публикацией.

## Границы доказательств DT-24

Guard — слой защиты, а не доказательство отсутствия любых производных. Сверяются целые нормализованные строки/ячейки и окна до 64 слов/4096 символов в тексте. Он не распознаёт фотографии/скриншоты (OCR отсутствует), шифрованные архивы, произвольное кодирование, PDF-сжатие, NSIS/7z/EXE-сжатые ресурсы и изменённые значения. Такие материалы нельзя включать в артефакты; проверять распакованный staging ДО упаковки, затем gate на конечном наборе файлов. Общие короткие значения могут давать ложные срабатывания; запрещено добавлять исключения для реальных данных.

DT-24 целиком не объявляется PASS только по этому guard: остаются проверка всей Git-истории, закрытых локальных логов/LLM-вызовов и всех фактических каналов публикации координатором. При обнаружении ранее tracked-конфиденциального файла остановить публикацию, исключить его из индекса без удаления оригинала; очистку истории и ротацию раскрытых ключей согласует координатор. Агент не открывает оригинал и не меняет его.

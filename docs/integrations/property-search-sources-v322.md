# Источники поиска v3.2.2: разрешённые подключения и ручная проверка

Статус LIVE на 08.11.2026 — в [../vkr/live-search-v322.md](../vkr/live-search-v322.md).
Автоматический обход CAPTCHA/антибот-защиты **не реализован и запрещён**: только ручное прохождение
сотрудником в браузерной сессии и разрешённые площадкой способы. Продакшн-учётные данные не хранятся
в репозитории; фиды/ключи подключаются через ENV/конфигурацию (см. `.env.example`).

## Что уже есть в CRM (без новых зависимостей)

- Импорт официальных выгрузок: `src/modules/property-search/infrastructure/official-feed.ts` —
  CSV/XLSX/XML, preview без записи в БД, лимиты 10 МБ/1000 строк (макс. 5000), XML без DTD/entities.
  Распознаются подмножества **Avito Autoload** (Ads/Ad, OperationType, ObjectType/CommercialType, Price,
  Square/Area, City, Address, Url/AdUrl) и **Яндекс XML** (offer/internal-id, commercial-type/category,
  price/value, area/value, location/locality-name/address, creation-date, last-update-date), плюс общие
  CSV/XLSX-колонки. Подтверждено REPLAY-тестами (`v31-manual-feed.test.ts`); LIVE-импорт реальной карточки
  заявлен только для onrealt/mirkvartir/yandex (p0a-final-ai.json).
- Добавление по ссылке: `manual-listing.ts` (`addListingByUrl` → `manual_required` при блоке) + ручная форма.
- Ручная CAPTCHA-сессия: полный цикл описан в [captcha-hitl.md](captcha-hitl.md) — `StartBrowserSession`,
  временный профиль Chromium, ввод только сотрудником, продолжение в том же context/page, `collect` тем же
  парсером, cookies живут только в изолированном профиле. Отдельный стенд: `tests/fixtures/captcha-stand/`.
- Ограниченному источнику UI предлагает «Добавить по ссылке» / «Импорт выгрузки» (search-results-v31).

## Официальные пути по площадкам (проверять с провайдером и договором агентства)

Ниже — направления для профаккаунта агентства, а не готовые интеграции и не утверждение о доступности.
Перед внедрением свериться с актуальной документацией площадки и условиями использования.

| Площадка | Разрешённый путь | Состояние в CRM |
|---|---|---|
| Циан | XML-фид агентства / API профессионального кабинета (размещение и выгрузки) | Импорт выгрузки сотрудника (CSV/XLSX/XML); чтение выдачи — только ручная браузерная сессия |
| Авито | Avito Autoload (XML-выгрузка объектов) + API бизнес-кабинета по ключу | Распознавание Autoload-полей в импорте; чтение выдачи заблокировано (HTTP 439) |
| Домклик | Партнёрский API/выгрузки для агентств (по договору со Сбером) | Импорт выгрузки; чтение выдачи заблокировано (HTTP 401) |
| Яндекс Недвижимость | YML/фид размещения для партнёров (сторона чтения публичного API не предоставляется) | Подмножество Яндекс XML в импорте; ограниченное чтение + ручной путь |
| Мир Квартир | Прямого публичного API нет — чтение публичной выдачи, официальные выгрузки по запросу | LIVE-чтение работает; ручной путь и импорт |
| OnRealt | Прямого публичного API нет — чтение публичной выдачи | LIVE-чтение работает; торговля через категорию ПСН (охват неполный, честно показан) |
| Юла | API бизнес-кабинета для размещения (сторона чтения ограничена) | LIVE-чтение работает, включая корректный ноль; жилая — unsupported_filter |

Правила: ключ/фид агентства хранится только в серверном ENV секретов, никогда в Git/логах/бекапах;
каждый новый адаптер — за тем же `ScraperAdapter`-швом с явными статусами (success/partial/blocked/
needs_user_action/unsupported_filter), unit-тестами на REPLAY-фикстурах и записью в эту таблицу.
Пароли, токены сессий, паспортные и регистрационные данные, закрытые контакты собственников в провайдер
AI и в логи не отправляются (см. redact/tests `search-ai.test.ts`).

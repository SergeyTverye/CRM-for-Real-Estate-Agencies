# Инженерные допущения реализации

Фиксируются решения по вопросам, которые ТЗ v1.6.1 допускает трактовать по-разному.
Формат: что было неоднозначно → решение → почему → что затрагивает.

## A-01. Видимость потребностей, обращений и показов риелтору
- **Неоднозначность:** ТЗ: «риелтор видит только своих клиентов» и «связанные с ними оперативные данные»; у ClientNeed/LeadRequest есть собственный `responsible_user_id`.
- **Решение:** риелтор видит ClientNeed/LeadRequest, если он ответственный за запись **или** за её клиента. Showing/CommercialOffer/NeedPropertyMatch — через доступ к потребности (или собственная ответственность).
- **Почему:** после передачи клиента руководителем обязательства риелтора не должны «исчезать» (ТЗ 40.1), но чужой клиент не раскрывается.
- **Затрагивает:** `src/modules/access/domain/scopes.ts`, все выборки, поиск, экспорт, выдачу файлов.

## A-02. Ответ на запрос недоступной записи
- **Решение:** для конкретной записи (чужой Client по ID, файл недоступной сущности) API возвращает `404 NOT_FOUND`, для функций роли (админка, архив, импорт) — `403 FORBIDDEN`.
- **Почему:** ТЗ 32.1 — внешний ответ не раскрывает сведений о недоступных объектах; 404 не подтверждает существование записи.
- **Затрагивает:** application-сервисы, `src/server/api-handler.ts`, authorization-тесты.

## A-03. Документы объекта недвижимости
- **Неоднозначность:** каталог объектов виден всем риелторам, но «доступ к связанным файлам» подчиняется правилу контактов собственника (ТЗ 17.2).
- **Решение:** фото объекта (`document_type_code=photo`) доступны всем, кто видит каталог; прочие документы объекта (правоустанавливающие, договоры) — только при доступе к контактам собственника (ответственный, grant, руководитель).
- **Почему:** такие документы обычно содержат ПДн собственника.
- **Затрагивает:** `documentScope()`, выдача файлов, поиск.

## A-04. Назначение ответственного за задачу
- **Решение:** руководитель назначает любого активного сотрудника; риелтор — себя, ответственного по потребности или руководителя (эскалация).
- **Почему:** ТЗ 32.1 — сервер не доверяет произвольному `user_id` из формы.

## A-05. «Task возврата» для paused
- **Решение:** любая незавершённая (planned/in_progress) Task, связанная с потребностью через `task_needs`. Отдельного типа «возврат» в codebook нет; UI формирует такую задачу с заголовком «Вернуться к потребности».
- **Затрагивает:** `src/modules/needs/domain/need-invariant.ts`.

## A-06. Просрочка
- **Решение:** задача просрочена, если она открыта и `due_at < now()` (а не «раньше начала текущих суток»). «Сегодня» — срок от текущего момента до конца локальных суток `APP_TIMEZONE`.

## A-07. Первичные учётные записи
- **Решение:** seed создаёт руководителя и двух риелторов с паролями из `SEED_*_PASSWORD`, которые генерирует `scripts/bootstrap.sh`; при первом входе требуется смена пароля. Существующие пользователи seed не изменяет.

## A-08. Юридические субъекты
- **Решение:** seed создаёт «ООО «Магазин недвижимости»» и ИП с наименованием-заглушкой; реальные реквизиты вносит руководитель (Администрирование → Юрлица). Реквизиты ИП являются ПДн и в репозиторий не попадают.

## A-09. Сервис migrate выполняет и seed
- **Решение:** одноразовый `migrate` выполняет `prisma migrate deploy && prisma db seed`; seed идемпотентен.
- **Почему:** штатная установка должна сводиться к `bootstrap.sh && deploy.sh` (ТЗ 36.6).

## A-10. Типы операций
- **Решение:** операция потребности (со стороны клиента): `buy`, `rent`, `sell`, `lease_out`; операция объекта: `sale`, `rent`. Подбор: `buy → sale`, `rent → rent`. Это бизнес-справочники, предприятие может их расширять.

## A-11. Район
- **Решение:** `district` — свободный текст с подсказками из уже введённых значений, а не справочник: реальный перечень районов предприятия в ТЗ не задан.

## A-12. Учётные данные контейнеров
- **Решение:** контейнеры `app`, `migrate`, `backup` работают от uid/gid владельца каталогов `data/` и `backups/` (`APP_UID`/`APP_GID` задаёт bootstrap; по умолчанию 1000).
- **Почему:** bind mount `./data/files` (ТЗ 36.2) должен быть доступен на запись без ручных chmod.

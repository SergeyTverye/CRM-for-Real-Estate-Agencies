# Контекстный AI-чат — ТЗ v3.1 §7, AT-16

Реализация: `src/modules/ai-chat/**`, `src/app/api/v1/ai-chat/**`, `src/ui/ai-chat/panel.tsx`. Кнопка «AI-помощник» в общей шапке. Отдельная личная история; руководитель также не читает чужие сессии.

## Контракт и использование

Новый диалог привязывается к открытой карточке `/clients/{id}`, `/needs/{id}` или `/collections/{id}`; на остальных страницах контекст общий. При смене страницы прежний диалог сохраняет прежний контекст — для нового используется кнопка «Новый диалог». В историю сохраняются очищенные сообщения; UUID заменяются в отображении ссылками с бизнес-названиями. В модель клиент передаётся псевдонимом и ID, реальные названия остаются только в разрешённых серверных ссылках для UI.

| Метод | API относительно `/api/v1/ai-chat` | Назначение |
|---|---|---|
| GET | `/sessions` | До 30 личных сессий |
| POST | `/sessions` | `{context:{kind:none/client/need/collection,id?}}` |
| GET | `/sessions/{id}` | Последние 40 сообщений, до 20 действий; повторная проверка контекста и сохранённых ссылок |
| POST | `/sessions/{id}/messages` | `{text}`: 1–4000 символов; ответ после ограниченного цикла модели |
| POST | `/sessions/{id}/actions/{actionId}` | `{decision:confirm/reject,confirmed:true}`; только владелец сессии |
| POST | `/sessions/{id}/web-search` | `{query,confirmed:true}`: 1–500 символов, отдельное платное действие |

Все маршруты используют существующий `api()` с аутентификацией, CSRF/Origin и standby-guard. Чужая сессия, клиент, потребность или закрытая подборка → 404. Вложения не загружаются и не отправляются провайдеру. Для больших операций есть индикатор, ошибки и обновление данных; введённое сообщение сохраняется при ошибке/закрытии панели. Есть предупреждение перед уходом со страницы.

## Серверные инструменты

- `find_clients`: только `clientScope`, без контактов и имён в модельном DTO.
- `get_tasks`: `taskScope` + `safeTaskTextScope`; свои задачи либо задачи доступного клиента.
- `client_timeline`: существующий `getClientTimelinePage`; только очищенные заголовки/статусы, без документов и контактных DTO.
- `find_listings`: собственные объекты каталога и личные закладки/сохранённые результаты/доступные подборки. Только необходимые публичные поля.
- `find_collections`: личные и общие подборки, до четырёх ID позиций в каждой.
- `compare_properties`: 2–4 доступных собственных/сохранённых объекта; числовые факты и очищенный публичный текст. Неизвестные значения остаются неизвестными.
- `prepare_task`, `prepare_offer`: только `AiPendingAction(status=proposed)`, срок действия 24 часа. Строгие Zod-схемы запрещают дополнительные поля и команды исполнения.

Отклонение пишет лишь решение/аудит, не создаёт Task/CommercialOffer. Подтверждение блокирует строку `AiPendingAction FOR UPDATE`, повторно проверяет права и выполняет `createTask` или `createOffer` в той же транзакции. Повторные/параллельные подтверждения не создают дублей. Точечный обратно совместимый параметр `existingTx?` добавлен в эти два сервиса; их обычные вызовы не изменены. КП сохраняет нормальные snapshots штатным сервисом.

Чат не предоставляет инструмента прямой записи CRM, SQL, shell, файлов, изменения ответственного или публикации. Внешний платный поиск не включён в инструменты модели: только отдельная кнопка → предпросмотр стоимости → подтверждение → `chat_web` через AiGate. Core работает без включения ИИ.

## Responses API и ограничения

Формат проверен 05.11.2026 по [описанию function calling Yandex](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/function-call) и [спецификации Responses.createResponse](https://aistudio.yandex.ru/en/docs/ai-studio/api/Responses/createResponse). Концептуальная статья показывает иной API генерации, поэтому для Responses используются `tools:[{type:function,name,parameters}]`, `function_call` и `function_call_output` с одинаковым `call_id`. Для продолжения локально передаётся массив input; `store:false`, без облачной истории. Ответ только с функцией также считается допустимым.

Максимум 4 вызова модели на сообщение (на последнем шаге новые инструменты не исполняются), до 4 функций за шаг, до 10 строк результата, 24 000 символов контекста и 9 000 символов одного JSON-результата. История для модели — последние 6 сообщений. Выход — до 1200 токенов, дополнительно ограничен ENV. Нет автоматических платных повторов. `AI_STEP_LIMIT`, `AI_CONTEXT_LIMIT`, `AI_RATE_LIMIT`, `AI_BUDGET_EXHAUSTED` возвращаются как понятная ошибка без последующего вызова провайдера.

Каждый HTTP-вызов: AiGate.check с резервом → AiUsageLog → AiChatMessage.aiUsageLogId → provider → settle. Ошибка до отправки освобождает резерв; неопределённая транспортная ошибка сохраняет консервативный резерв. Для web резерв учитывает тарифный запас входных токенов. `jobId` бюджета соответствует одному сообщению/внешнему поиску, связь со всей сессией — через сообщения. Действующие `perJobLimit`, суточные/часовые ограничения и бюджет не обходятся; для диалога с инструментом руководителю обычно нужен `perJobLimit >= 2`.

Общий клиент Yandex расширен только поддержкой типизированных функций/массива input; существующие поисковые tools остаются обратно совместимыми. Коды `chat`/`chat_web` добавлены в codebook и ограничение БД отдельной миграцией `20261106020000_ai_chat_call_types`. `schema.prisma` не менялась. Это SQL CHECK, не представимый Prisma schema/migrate diff; миграция вручную расширяет только существующий CHECK. Её нужно включить координатору вместе с миграцией модели v3.1.

## ПДн и prompt injection

Белые списки выбираемых полей, серверный RBAC и повторная проверка ссылок предшествуют выдаче данных. Пароли, токены, cookies, паспорт, регистрация, дата рождения и owner contacts не читаются инструментами. Свободный текст проходит существующий p2-санитайзер, дополненный удалением секретов. Известные имена доступных клиентов/контактных лиц используются только для серверного удаления, не отправляются как словарь. ISO-время и UUID защищены от ошибочного удаления как телефон; отдельная регрессия фиксирует это.

Тексты объявлений и история передаются в `untrusted_data`; результаты функций — JSON. Системная инструкция запрещает исполнение команд из данных. Неизвестное имя инструмента отклоняется до исполнения. Prompt injection может испортить ответ модели или предложить черновик, но не выполнить CRM-изменение: независимая кнопка и серверная проверка остаются обязательными. React выводит текст, не HTML/произвольные ссылки модели.

### Причина и поведение

Это не подтверждённый дефект кэша Next: POST/GET уже отвечают `Cache-Control: no-store`; новая API-регрессия проверяет этот заголовок. Воспроизведён сбой: `prepare_task` сохраняет `AiPendingAction`, затем следующий вызов останавливает AiGate (`perJobLimit=1`). Раньше API возвращал 422, а `send()` панели присваивал новое состояние только при успешном POST. Сохранённый черновик становился виден после ручного GET/refresh.

Теперь при AiError после сохранения нового черновика API возвращает текущий разрешённый снимок с `warning`; ошибки до черновика сохраняют прежний error response. Панель сразу присваивает ответ POST; при API/transport-ошибке сама читает историю одним GET. Повторный платный POST не выполняется. Неудачный GET по сети сохраняет выбранный диалог, 403/404 очищает недоступное состояние. `useRef` блокирует пересечение операций, в том числе при закрытии/открытии панели во время запроса. Await финального `getChat` удерживает серверный busy guard до окончания выдачи снимка.

### Подписи и минимизация ПДн

Разрешённые названия в контексте и tool data заменяются на `[[id]]` **до** санитайзера. Словарь имён и подписи `links` провайдеру не отправляются. Сервер сохраняет ссылки отдельно, повторно проверяет RBAC перед выдачей и восстанавливает подпись клиента из CRM; UI показывает именную ссылку по `[[id]]`. Названия черновиков восстанавливаются по этим же разрешённым ссылкам; подтверждение Task сохраняет обычное название через существующий CRM service в транзакции. Заголовок истории не обрезает UUID-ссылку и не показывает её пользователю.

Небольшой закрытый словарь обычных команд («Подготовь», «Уточнить», «Проверить» и т. п.) защищён от ложного определения как имени. ISO/UUID и ограниченные адресные конструкции, например «улица Кирова, 25», сохраняются. Контакты, ФИО, паспорт, регистрация и секреты по-прежнему удаляются. Старые `[PERSON]` без однозначной ссылки невозможно достоверно восстановить: UI пишет «данные скрыты», а доступные записи подписывает серверными именами. Привязка произвольного `[PERSON]` к случайному клиенту не выполняется.

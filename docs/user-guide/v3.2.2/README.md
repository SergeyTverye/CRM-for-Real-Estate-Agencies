# Редактирование и сборка руководства

Основной редактируемый источник — `guide.md`. Скриншоты и размеченные рисунки
находятся в `images/`. Готовый PDF лежит рядом. Изменения продукта не входят в эту
задачу; примеры учебные, внешние поиски и платные AI-команды не запускаются.

## Сборка

Требуются Python 3 с `reportlab`, `Pillow`, кириллические Arial и Poppler
(`pdftoppm` в PATH). Версии среды фактической сборки указаны в протоколе проверки.
Команды выполняются из корня репозитория:

```powershell
python scripts/docs/build-user-guide.py --render
```

В Codex используйте Python из `load_workspace_dependencies`, поскольку Python
системы может не содержать reportlab. На другой ОС передайте
`--font-dir /path/to/fonts` с `arial.ttf`, `arialbd.ttf`, `ariali.ttf`.

Сборка автоматически добавляет титул, оглавление с физическими номерами страниц
и ссылками, закладки, колонтитулы и встраивает шрифты. Один раздел начинается
с новой страницы. При переполнении страницы сборка завершается ошибкой:
разделите длинный раздел на два, а не уменьшайте шрифт до нечитаемого размера.
После изменения текста или снимков заново проверьте все PNG в
`tmp/pdfs/guide/page-*.png`. Контактные листы `sheet-*.png` помогают ориентироваться,
но не заменяют просмотр отдельных страниц.

## Новая съёмка

Только синтетический стенд `http://127.0.0.1:3373`, уже запущенный координатором:

```powershell
node --env-file=.env scripts/docs/guide-screenshots.mjs http://127.0.0.1:3373
python scripts/docs/build-user-guide.py --render
```

Координатор выполнил съёмку текущей сборки на синтетическом стенде: 36 снимков.
Формы договора, очередь, повтор и оба документа получены. Шаг поиска завершился
без полного набора кадров сравнения; по указанию координатора повторов больше нет.
Выдача и анализ для PDF взяты из готового LIVE-протокола `v322-search-ai`, таблица —
из синтетического P0-C. Все использованные области просмотрены на отсутствие
ключей и контактов продавцов. Windows-иллюстрации v3.2 оставлены для локального режима.

Скрипт получает учётные данные из окружения и не выводит их. API-вход выполняется
для manager/realtor1. Навигационные запросы браузера ограничены GET/HEAD локального
стенда. Исключение — создание синтетического клиента и договора с двумя учебными
PDF. Второй POST документа намеренно получает 503 от Playwright; повтор должен
загрузить только неудачный файл и открыть документы. Это не ошибка сервера.
Сессии и пароли не сохраняются. Размер окна 1440×900, deviceScaleFactor 2.
Поиск и AI-вызовы запрещены перехватчиком независимо от кнопок интерфейса.

При съёмке сведения записываются в `images/live/manifest.json`, bounding box —
в JSON рядом с каждым PNG. Manifest честно сохраняет неуспешные шаги;
источники исторических снимков,
координаты обрезки и выносок — `images/figure-sources.json`. Старые снимки Windows
явно подписаны как v3.2; это не новые native Windows-проверки.

Автоматическая структурная проверка (нужны `pypdf` и `pdfplumber`):

```powershell
python scripts/docs/check-user-guide.py
```

Проверяется число страниц и закладок, каждый адрес оглавления, кириллица,
встроенные TrueType-шрифты и границы текста. Итоговый протокол — `qa.md`.

## Источники содержания

- `docs/user-guide.md`, `docs/user-guide-property-search.md`.
- `docs/ux/v322-ux-audit.md` — маршруты и компактные формы.
- `docs/acceptance/v322/agreement-documents.md` — очередь документов договора.
- `docs/vkr/live-search-v322.md`, `docs/vkr/live-search-v322-ai.md` — ограничения
  площадок и AI; эти отчёты не равны новым LIVE-вызовам при создании руководства.
- `docs/desktop/install.md`, `backup-format.md`, `backup-settings-api.md` —
  локальное хранение, копии, облака, ограничения установленного приложения.
- Фактические надписи текущего UI и сохранённых синтетических снимков.

Файл `ТЗ.txt` отсутствует в этой рабочей копии и в корне родительского проекта.
Задача руководства выполнена в границах отдельного поручения P1-B по существующей
CRM; исходники приложения, секреты и реальные Excel-данные не изменялись.

# P1: отчёты, настройки ИИ и мобильный интерфейс

Дата: 05.11.2026. Ветка: feature/tz-v2.4.1, общая рабочая копия; коммит выполняет координатор.
Версия снятого приложения: HEAD 3396fe3 плюс незакоммиченные параллельные изменения этапа P1. Данные — синтетическая crm_demo из docs/vkr/demo-data.md; размеры desktop 1440×1000, mobile 360×860 и 430×860.

## Изменения

- Детализация отчётов: название показателя и фильтров, клиент и объект со ссылками по имени/адресу, сотрудник, русский источник и статус; даты `dd.mm.yyyy hh:mm` в настроенном `Asia/Novosibirsk`. Для комиссии используются её статус и дата получения. Выборки и формулы report-service не изменены. Пагинация по 50 строк сохраняет срез; enrichment использует существующие application queries и RBAC.
- Настройки ИИ: сохранённые и эффективные ограничения, ENV-разрешения и потолки, зависимости режимов, бюджет текущего месяца, учтённый расход, резерв и доступный остаток. Отдельные лимиты веб-заданий/вызовов, часовой предел и потребление сегодня по каждому сотруднику. Для подсчёта используются все страницы авторизованного журнала, включая резервы; временные границы — локальные сутки/месяц. Секреты в клиентские props не передаются.
- Дата версии тарифа вводится через DateTimeInput с часовым поясом CRM, а не браузера. Сохранение даёт toast и результат формы.
- Мобильные списки обращений, клиентов, задач и объектов: серверные `data-label` и общий класс `mobile-card-table`; без изменения выборок или DOM после гидратации. Нижняя панель «Сегодня / Создать / Задачи», меню создания, цели нажатия от 44 px, липкие действия основных форм, прокрутка вкладок задач внутри панели. Standby скрывает создание.
- Общий `src/ui/confirm-dialog.tsx`: ConfirmDialog и асинхронный requestConfirmation(message). Отмена и Escape возвращают false, фокус возвращается на инициатор. Поддерживаются подтверждения поверх существующего Modal. Заменены native confirm в ActionButton, задачах, объектах, пользователях, справочниках и юрлицах. Чужие зоны не редактировались.

## Ограничения и границы

- Текущий DTO отчёта не содержит точного времени коммуникации или события реактивации; вместо подмены датой изменения клиента выводится «—». Имя сотрудника коммуникации берётся из activity-среза. Для точных event timestamps потребуется отдельное расширение DTO модулем отчётов.
- Метрики и суммы не менялись; после параллельных изменений общей копии требуется финальный общий QA координатора.
- Схема БД, миграции, зависимости, .env не менялись; npm install не выполнялся. Коммитов/переключений веток не было.
- Собственный dev-сервер 3350/.next-rep остановлен после проверки; чужие серверы не останавливались. Сгенерированные пути .next-rep/types в tsconfig.json оставлены для очистки координатором согласно его инструкции.

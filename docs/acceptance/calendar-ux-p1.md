# P1: календарь, Сегодня, уведомления и обзор клиента

Дата: 05.11.2026. Ветка: `feature/tz-v2.4.1`, общая рабочая копия. Данные исключительно синтетические.

## Изменения

- Календарь: варианты повторения вместо редактирования RRULE; будни, выбранные дни недели, ежемесячно, до локальной даты включительно или 1–1000 встреч. Изменение существующей встречи меняет серию. Месяцы без нужного числа пропускаются. Хранение совместимо с прежними правилами; миграция не нужна.
- Имена CRM-связей выбираются через `GET /api/v1/calendar/links?type=clientId|needId|propertyId|dealId&q=...`. Возвращается до 20 `{id,label}`. Клиентская граница совпадает с проверкой команды сохранения: доступ к потребности/сделке не разрешает раскрывать чужого клиента. При открытии встречи возвращаются проверенные подписи выбранных связей.
- Пересечение — предупреждение после сохранения, без блокировки команды и без раскрытия чужих названий. Проверяются интервальные встречи, для новой серии горизонт 90 дней. Нативные confirm/alert заменены общими диалогами и предупреждением на странице. Escape проходит через проверку несохранённых изменений (`Modal.onCancel`, точечное обратно совместимое изменение).
- «Сегодня»: сначала задачи и срочные действия, затем повестка и контрольные даты. «Просрочено» считает только открытые задачи со сроком раньше текущего момента; «На сегодня» — от текущего момента до следующей локальной полуночи; показы и контрольные даты показаны отдельно. Служебные задачи показов исключены, реальные показы берутся из Showing.
- Шапка всегда показывает свои просроченные задачи. В режиме «Мои» её predicate совпадает с `/today` и списком задач; для «Все» и сотрудника указан другой охват. Верхний счётчик и заголовок блока используют одну полную count-выборку. В каждом временном блоке показывается до 200 задач, большие очереди не вытесняют следующие блоки. Отдельно до 200 сегодняшних показов. Ограничение вывода явно подписывается.
- Перспективные без актуального действия используют существующий `getContactControl`, счётчик и список берутся из одного результата. В него также попадают обращения с уже просроченной задачей — это существующее правило актуальности, не новая семантика.
- Уведомления: текст, доступный клиент/объект и срок реконструируются по актуальным источникам. Историческим `title/link` не доверяем. Все прямые и косвенные клиентские связи задачи проверяются перед раскрытием текста. Произвольная задача, созданная другим сотрудником без проверяемого бизнес-контекста, сохраняет нейтральное название. Передача клиента немедленно скрывает прежний контекст.
- Однотипные уведомления сгруппированы по дню CRM внутри текущей страницы; каждое сохраняет собственную ссылку, прочтение и snooze. Счётчик колокольчика считает уведомления, не группы. Пагинация сохраняет фильтр. Ссылка встречи открывает её редактор через `/calendar?eventId=...`.
- Обзор клиента: последние пять коммуникаций/показов/КП/задач, сортировка по фактическому моменту взаимодействия или последнему изменению. Служебные задачи показов не дублируются. «Следующее действие»: выполнить, перенести, создать через действующие формы с optimistic concurrency и инвариантами. Включены задачи, связанные только через потребность, показ, КП, договор или сделку.

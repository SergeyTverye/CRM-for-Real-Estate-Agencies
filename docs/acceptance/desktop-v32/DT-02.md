# DT-02

**Статус: BLOCKED**

Условие PASS из ТЗ v3.2.1: То же на Windows 11 x64; WebView2 и необходимые runtime доступны после офлайн-установки.

Данные: синтетика. Для DT-22/23 — только доверенный локальный verifier с обезличенным выводом.

Фактический результат: Чистая потребительская Windows 11 x64 офлайн-VM недоступна по явному решению пользователя. На текущем рабочем Windows 11 ПК в изолированных синтетических профилях официальный установщик `71e8765` ([EXE-артефакт GitHub Actions](https://github.com/SergeyTverye/CRM-for-Real-Estate-Agencies/actions/runs/42396531730/artifacts/13584259822), 585 603 587 байт, SHA-256 `a3e5ab26cbe6bcd249f2f222994052c4f985541c46b81910b9221d3262be311e`, встроенные Node 24.15.0, SQLite 3.51.2, Chromium 156.0.8078.4) установился с `exit 0`, открыл штатное окно Tauri с мастером первого запуска и экраном входа после перезапуска, а также прошёл автоматизированный lifecycle на Windows Server 2022/2025 в CI ([протокол `71e8765`](installed-71e8765.md), [реестр артефактов](../../desktop/release-artifacts.md)). Текущий ПК и Windows Server CI не эквивалентны чистой потребительской Windows 11 VM после офлайн-установки.

Следующее действие: карточка остаётся BLOCKED по решению пользователя об отсутствии чистой потребительской Windows 11 x64 VM; при предоставлении чистой офлайн-VM — проверить офлайн-установку финального EXE и доступность WebView2/runtime на чистой Windows 11 x64.

Срез подтверждений: текущий исходный срез `bf8538d` (правки очистки при overinstall и генерации `offer.pdf` ожидают сборки следующего EXE); проверенный установщик — `71e8765` (Run `42396531730`). Исторические срезы `11a2778`, `7e7e47e`, `41c39b8` (`b56ec7501a9b9ebc9328f9e1dfc03cf452b8e10611bae0675bb4eb6f4262126b`) и `278b54f` сохранены как архивные. Условие чистой потребительской Windows 11 VM остаётся BLOCKED.

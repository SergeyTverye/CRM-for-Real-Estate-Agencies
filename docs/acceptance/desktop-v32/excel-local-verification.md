# Excel: обезличенный итог доверенной локальной проверки

## Актуальная локальная проверка 2026-11-07

Координатор выполнил trusted verifier на новых изолированных SQLite и PostgreSQL
БД после реализации control target и исправления per-row baseline экспорта. На
каждой БД все 24 проверки = 1, errors={}, unresolved=0, mismatchCoordinates=[].
Исходная книга не изменилась; временные БД и копии удалены проверяющим средством.
Значения книги и закрытого профиля внешним моделям не передавались.

359 распознанных строк: 127 импортировано (8/14/4/90/11 по первым пяти листам),
128 исключено по hidden policy, 104 отклонено. Одиннадцать строк контрольной
таблицы теперь создают нормализованные связи договора/рекламы/объекта; остальные
неоднозначные форматы не были принудительно преобразованы. Dry-run без business
write, fault-injection rollback с проверкой связанных таблиц, подтверждение,
повторы, RBAC и нулевой повторный импорт экспорта прошли на обоих бэкендах.

Расхождений нет для 127 row keys, 201 ключевого поля, 48 денежных значений,
90 контактов и 90 дат; control presence/absence по 11, scalar/advertising по 22.
Сохранены проверяемая геометрия шести листов, 4640 numformats, 90 headers,
defined names/sections/order. Compatibility: UNSUPPORTED_COLUMN=30,
UNSUPPORTED_FIELD=90, HYPERLINK_CLEARED=32, IMAGE_PRESERVED=15, FORMULA_CLEARED=0.
Формул в исходной книге нет; их работа подтверждается отдельной синтетикой.

Сначала этот же усиленный verifier обнаружил семь расхождений и нарушение
reimport: контрольные строки брали общие поля ранее существовавшего Property.
Исправление хранит закрытую проекцию полей на момент commit в существующем
ImportJob summary и сохраняет допустимые поля исходной строки, пока CRM-значение
не изменилось. Реальные последующие изменения CRM экспортируются; старые jobs
без baseline не получают выдуманной истории. До/после проверены локально.

Закрытый профиль остаётся локальным кандидатом для выбранных поддерживаемых
полей. Это ограниченный verifier, не утверждение полного качества всех строк,
пользовательской апробации или установленного EXE. DT-22/23 остаются PARTIAL.

В реальном файле формулы отсутствовали: `FORMULA_CLEARED=0` **не доказывает сохранение формул**. Отчёт не обещает бинарного тождества исходной книге. Неоднозначные строки отклонены, контрольная таблица остаётся неподдерживаемой; `unresolved=0` не означает полное покрытие всех данных. Поэтому [DT-22](DT-22.md) и [DT-23](DT-23.md) остаются **PARTIAL**, хотя ограниченный локальный verifier прошёл на обеих БД. Проверка установленной Windows CRM этим не заменяется.

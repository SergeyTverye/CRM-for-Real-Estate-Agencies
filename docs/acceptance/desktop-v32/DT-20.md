**Статус: PARTIAL**

Условие PASS из ТЗ v3.2.1: Повторная установка после обычного удаления открывает прежние документы и SQLite. Полное удаление по отдельному подтверждению очищает разрешённые каталоги/секреты, не затрагивая shared runtimes и облачные архивы.

Данные: синтетика. Для DT-22/23 — только доверенный локальный verifier с обезличенным выводом.

Фактический результат: В Windows CI официального установщика `71e8765` ([EXE-артефакт](https://github.com/SergeyTverye/CRM-for-Real-Estate-Agencies/actions/runs/42396531730/artifacts/13584259822), SHA-256 `a3e5ab26cbe6bcd249f2f222994052c4f985541c46b81910b9221d3262be311e`, [протокол `71e8765`](installed-71e8765.md)) на Windows Server 2022 и 2025 (`installer-evidence-windows-2022`, `installer-evidence-windows-2025`) прошли повторная установка после обычного удаления с открытием сохранённых данных и полное удаление (purge) синтетического контрольного файла, регистрации, ярлыков и процессов. Однако пользовательский цикл повторной установки и полного удаления с подтверждением на текущем Windows 11 ПК для финального EXE (после правок `bf8538d`), а также проверка неизменности облачных архивов при полном удалении на установленном ПК ещё не выполнены; чистые потребительские Windows 10/11 VM остаются BLOCKED по решению пользователя.

Следующее действие: на следующем собранном EXE со срезом `bf8538d` проверить на Windows 11 ПК повторную установку после обычного удаления с открытием прежней SQLite и документов, а затем полное удаление по отдельному подтверждению с проверкой очистки разрешённых локальных каталогов/секретов при сохранности shared runtimes и облачных архивов.

Срез подтверждений: текущий исходный срез `bf8538d`; проверенный официальный установщик — `71e8765` ([реестр артефактов](../../desktop/release-artifacts.md)). Исторические срезы `11a2778` и `41c39b8` сохранены.

Данные: синтетика. Для DT-22/23 — только доверенный локальный verifier с обезличенным выводом.

Фактический результат (актуальный прогон 2026-11-07): доверенный локальный verifier после добавления target `property_agreement_control` и исправления per-row baseline прошёл на новых изолированных БД **PostgreSQL и SQLite** — на каждой все 24 булевы проверки = 1, `errors={}`, `unresolved=0`, `mismatchCoordinates=[]` ([актуальный протокол Excel](excel-local-verification.md)). Из 359 распознанных строк на 6 листах импортировано **127 строк** (8, 14, 4, 90, 11 по первым пяти листам, включая 11 строк контрольной таблицы, создающих нормализованные связи договора/рекламы/объекта/задачи), 128 исключено по политике скрытых строк, 104 неоднозначные строки отклонены. Dry-run без записи в бизнес-таблицы, откат при инъекции сбоя со сверкой связанных таблиц, идемпотентный commit, повторы, RBAC, нулевой повторный импорт экспортированного файла (0 новых записей), неизменность SHA исходной книги и очистка временных копий прошли на обеих БД. Неоднозначные строки (104), скрытые строки (128) и неподдерживаемые колонки/поля (`UNSUPPORTED_COLUMN=30`, `UNSUPPORTED_FIELD=90`) не форсируются, а импорт через UI и системный file picker установленной Windows CRM ещё не проверен, поэтому карточка остаётся **PARTIAL**.

Следующее действие: согласовать с пользователем итоговую политику в отношении 104 отклонённых неоднозначных строк и неподдерживаемых элементов книги и выполнить импорт/dry-run/commit через штатный UI и нативный диалог выбора файла в установленной Windows CRM без публикации закрытых данных.

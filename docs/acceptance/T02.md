# T02. Регистрация обращения для существующего и нового клиента, дубли, «чей объект»

- **Дата проверки:** 2026-11-03
- **Версия:** см. commit в `IMPLEMENTATION_REPORT.md`
- **Среда:** PostgreSQL 18.6 (compose.test.yaml), Node.js, Vitest 5 / Playwright 1.64

## Предусловия
Объект риелтора 2; клиенты риелтора 1.

## Тестовые данные
Синтетические клиенты и телефоны диапазона +7 900 000-…/+7 912 …

## Действия
1. Риелтор 1 регистрирует обращение по объекту риелтора 2 с новым клиентом и потребностью.
2. Обращение существующего клиента риелтора 1 по объекту риелтора 2.
3. Обращение без дальнейшей потребности.
4. Совпадение контакта с чужим клиентом → нейтральный конфликт → передача руководителю.
5. Руководитель видит кандидатов-дублей и создаёт нового клиента явно.

## Ожидаемый результат
Client/LeadRequest/ClientNeed нового клиента — у риелтора 2; у существующего клиента ответственный не меняется, конфликт показан; факт обращения сохраняется всегда; риелтору не раскрываются id/имя/ответственный чужого клиента; auto-merge отсутствует.

## Фактический результат
Совпадает с ожидаемым.

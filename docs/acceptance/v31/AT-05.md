Дата: 06.11.2026. Требования: ТЗ v3.1 SR-06, AT-05. **Статус: PASS (DEMO, контролируемый источник + production Docker runtime)**.

## Предусловия и данные

Все 7 существующих миграций, отдельная `crm_test_d` для integration и `crm_test_hitl_docker` для Docker; production Chromium с sandbox. Только синтетическая локальная площадка `tests/fixtures/captcha-stand`: после ввода «человек» выдаёт Cian SSR, распознаваемый штатным парсером. Constructor DI направляет transport в стенд, внешний browser DNS запрещён. Production SSRF-политика не ослаблена. Проверка не доказывает права или доступность реального Циана.

## Действия и ожидаемый результат

1. Создать задание штатной очередью; настоящий scraper/детектор получает страницу проверки → тот же SearchRun и источник `needs_user_action`.
2. Открыть сессию через аутентифицированный POST API (cookie + Origin). Подготовленный URL — `/cat.php` с region=4897 и условиями сохранённого задания. Получить JPEG через `/frame`; progress связывает источник с этой сессией.
3. Передать клик, текст «человек» и клик через API `/input`. Browser-managed HttpOnly cookie остаётся в том же контексте; guarded redirect возвращает исходную выдачу.
4. `/complete` → production parser → нормализация/проверка фильтров → результат и snapshot **в исходном SearchRun/источнике**, без второго браузера. `/results` возвращает одну карточку. Повторный complete не дублирует snapshot.
5. Сессия `completed/search_resumed`, frame=null, собственный профиль удалён. Viewer возвращает на `?runId=...`, штатный polling получает новую выдачу. Отдельная browser-регрессия проверяет ручной ввод из настоящего React viewer.
6. При повторной блокировке второй страницы: первая карточка сохранена, источник `blocked`, run `partial`, сессия `failed/blocked_again`; ручная ссылка/официальный импорт доступны.
7. Чужой руководитель получает 404 на metadata/frame/input/complete/cancel. Deadline → expired/blocked; отмена задания → cancelled/cancelled. Проверить общий лимит claims в PostgreSQL и запрет HTTP redirect на чужой домен.

# Разбор сбоев технического прогона AT-18

06.11.2026. Это подготовка апробации, а не результаты участия сотрудников.
Исходный прогон выполнялся на порту 3420; повтор — на 3424 с отдельным `.next-3424`.

| Сценарий | Причина и классификация | Исправление / проверка |
|---|---|---|
| S02, перспективный звонок | Ошибка скрипта: `sale` — код поиска/объекта, отсутствующий среди операций потребности. Playwright ожидал допустимую option и сообщал тайм-аут у `getByLabel('Операция')`. Само поле существует. | Выбор операции по отображаемому значению «Купить»; обе роли создают клиента, потребность и следующую задачу. |
| S05, руководитель | Ошибка скрипта: жёсткое название существующей DEMO-подборки. | Каждая проверяемая роль создаёт собственную подборку без клиента, добавляет объект, привязывает потребность и создаёт КП. |
| S05, риелтор, PARTIAL | Ошибка скрипта: placeholder с тремя точками вместо символа `…`, проверка до готовности workspace. | Ожидание `data-collection-ready=true`, выбор объекта по полю «Объект CRM»; полный путь до КП. |
| S10, риелтор | Ошибка тестовых данных: выбирался первый клиент без ограничения владельцем. Старый скриншот показывает «Запись не найдена или недоступна». Это штатный RBAC, не дефект карточки. | Выбор собственного DEMO-клиента для каждой роли; HTTP 200, заголовки и применение фильтра истории. |
| S10, руководитель, `ERR_ABORTED` | Сбой старого dev-окружения / ненадёжная навигация скрипта. В `.next-3420/dev/logs/next-development.log` есть `Manifest file is empty` и `Unexpected end of JSON input`; связывать именно этот запрос с предметным 500 оснований нет. Несохранённые формы также могли отменять переход. | Изолированный каталог сборки, обработка beforeunload на синтетическом стенде. Свежий серверный лог подтверждает HTTP 200 истории и фильтра у руководителя и риелтора; ошибки рендера карточки не воспроизведены. |
| S14, руководитель | Ошибка скрипта: ожидание `/requests`, тогда как штатный drill-down ведёт в `/reports/detail?...`. | Проверка фактического адреса детализации отчёта. |
| S08, чек-лист | Ошибки скрипта: произвольная задача без владельца и ожидание внутреннего `__reactProps` до действия. В повторе с собственной задачей HTTP 200 / видимая карточка тоже не удовлетворяла этой эвристике, а отдельная проверка клика немедленно открывала «Новый пункт». | Собственная синтетическая задача; ожидание публичного состояния DOM и фактического открытия диалога/сохранения пункта вместо приватных свойств React. |
| S12, AI-чат | Ошибки скрипта: чужой клиент приводил на 404 без общей панели; затем список диалогов читался до завершения загрузки. | Собственный клиент, ожидание DEMO-option; подготовленный локальный черновик, явное подтверждение, без вызова провайдера. |
| S13, PARTIAL / FAIL | Ошибки скрипта и окружения: CSV с URL ЦИАН загружался у другой площадки; `SCRAPER_DEMO_FIXTURES` не заменяет `SCRAPER_ENABLED`, отключённые источники не показывают импорт. | Оба процесса с `SCRAPER_ENABLED=true`; URL соответствует источнику выбранного действия, preview требует 2 кандидата и 0 ошибок. Записанный отказ — HTTP 429 / blocked, не CAPTCHA. |
| S03/S04 и ожидания поиска | Отключённые источники давали пустые счётчики; текстовое ожидание могло завершаться раньше обновления выдачи. | Проверка статуса конкретного задания и ожидание выдачи/группы; отключённые источники не выдаются за успешный поиск. |
| Очистка технического повтора | Ошибка скрипта: физическое имя FK элемента КП — `commercial_offer_id`, а не `offer_id`. Исключение прерывало восстановление fixture. | Исправлен FK, очистка ограничена созданными КП; восстановление AI-черновика и флагов защищено `finally`. Остатки промежуточного повтора удалены по доказанным связям аудита с маркером `APPROB-DRY`; аудит сохранён. |

Подтверждённых дефектов application-кода по этим сбоям не найдено; `src` и схема БД не менялись.
Регрессия существующих сервисов и RBAC на отдельной `crm_test_e`: `calls-timeline-v31` / `collections` — 24/24 PASS; `planner-v31` / `ai-chat` — 25/25 PASS (integration + authorization, всего восемь файлов).
Фактический результат полного браузерного повтора и времена — [dry-run](dry-run.md).
Живая CAPTCHA отдельно проверяется AT-05; субъективные оценки и дополнительные ручные шаги — в пользовательских бланках.
